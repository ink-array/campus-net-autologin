# 校园网开机自动登录（Dr.COM ePortal）

> 开机自动认证、掉线自动重连、图形界面管理、可随时更换任意学号与密码。
> 纯 PowerShell + WinForms，全部使用 Windows 自带组件，无第三方依赖、无后台服务、无遥测。

本项目与 Dr.COM（哆点）官方无关，是一个面向校园网用户的第三方自动化脚本。

---

## 它解决什么问题

很多高校用 Dr.COM ePortal 做上网认证：每天开机要手动打开浏览器、等门户页面加载、输入学号密码、点登录。换 WiFi、休眠唤醒、认证掉线之后还要再来一遍。

这个工具把这件事变成后台自动的：登录 Windows 后十几秒内自动认证，之后每 30 秒巡检一次，掉线立即重连。

---

## 功能

| 功能 | 说明 |
|---|---|
| 开机自动登录 | 计划任务在登录 Windows 后 15 秒触发，隐藏窗口运行，不闪黑框 |
| 掉线自动重连 | 30 秒巡检；失败按 30→60→120→300 秒退避，不会狂刷密码把账号打到锁定 |
| 图形界面 | 深色界面，显示连接状态、本机 IP/MAC、门户在线时长 |
| 任意账号 | 学号 + 密码随时可改，支持 `@cmcc` / `@dx` / `@lt` 运营商后缀 |
| 密码加密 | Windows DPAPI 加密存储，配置文件里没有明文 |
| 真在线判定 | 不只看接口返回值，还要外网 HTTP 200 才算成功 |
| 免管理员 | 全部在用户态运行，不写系统目录、不改全局注册表 |

## 环境要求

- Windows 10 / 11
- PowerShell 5.1（系统自带，无需安装）
- 已连上校园网（WiFi 或网线）——认证请求发往校内门户，外网不通时也能完成登录
- 已知本校认证门户地址（默认 `10.8.0.3:801`，多数学校相同）

## 快速开始

### 方式一：用便携包（推荐）

1. 到 **Releases** 下载 `校园网自动登录_便携包.zip`
2. 解压到本地磁盘，**不要在压缩包里直接双击**
3. 双击 `安装.cmd`
4. 在弹出的界面里填自己的学号和密码，点「保存并登录」

安装脚本会：把程序复制到 `%LOCALAPPDATA%\CampusNetAutoLogin`、生成隐藏窗口启动器、注册当前用户的计划任务、在桌面创建图标。**不需要管理员权限。**

### 方式二：从源码构建

```powershell
# 生成 dist\校园网自动登录_便携包 与 zip、SHA256
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

也可以直接用核心脚本，不装自启动：

```powershell
.\CampusNetAutoLogin.ps1 setup     # 交互式设置学号/密码
.\CampusNetAutoLogin.ps1 login     # 立即认证一次
.\CampusNetAutoLogin.ps1 status    # 查看门户在线状态
```

双击桌面图标打开：

| 区域 | 说明 |
|---|---|
| 顶部状态卡 | 绿点「已连接」/ 红点「未认证」，显示本机 IP、MAC、门户在线时长、当前账号 |

| 检测状态 | 重新探测外网 + 门户在线信息 |
| 开机自动连接 | 一键开启 / 关闭计划任务 |

## 命令行

```powershell
.\CampusNetAutoLogin.ps1 show                     # 看账号与自启动状态
.\CampusNetAutoLogin.ps1 status                   # 外网 + 门户在线时长
.\CampusNetAutoLogin.ps1 login                    # 登录（已在线会跳过）
.\CampusNetAutoLogin.ps1 login -Force             # 强制认证
.\CampusNetAutoLogin.ps1 setup -Account <学号> -Password '<密码>' -Suffix '@cmcc'
.\CampusNetAutoLogin.ps1 log                      # 最近 30 条日志
.\CampusNetAutoLogin.ps1 install                  # 重装/修复自启动
.\CampusNetAutoLogin.ps1 uninstall                # 卸载自启动并结束守护
```

`-Json -Quiet` 可让所有子命令输出机器可读的结果，便于二次开发。

## 登录是怎么发的

接口参数来自门户前端脚本（`a40.js`）的真实实现，不是猜测：

```
GET http://<portal>:801/eportal/portal/login
    ?callback=dr1003&login_method=1
    &user_account=,0,<学号>          # ",0," 为门户账号前缀，PC 端固定
    &user_password=<密码>
    &wlan_user_ip=<本机IP>           # 自动取默认路由网卡的 IPv4
    &wlan_user_mac=<本机MAC>
    &wlan_ac_ip=&wlan_ac_name=&jsVersion=4.1.3&terminal_type=1&lang=zh
```

返回 `{"result":1,...}` 表示成功。失败时依次尝试：换 MAC 写法 → 回退老接口 `http://<portal>/drcom/login`（`DDDDD` / `upass` / `0MKKey`）→ 退避重试。

在线判定刻意**避开** `generate_204`、`ncsi.txt`、`captive.apple.com` 这类地址——部分学校把它们放进了认证白名单，用它们探测会永远误判「已在线」。本工具使用 `msftconnecttest.com` 与 `baidu.com`。

## 开机与重连策略

| 场景 | 行为 |
|---|---|
| 登录 Windows 后 | 15 秒后由计划任务拉起守护进程（隐藏窗口） |
| 正常在线 | 每 30 秒探测一次外网，安静待命 |
| 掉线 / 切换 WiFi | 立即重新认证；失败按 30→60→120→300 秒退避 |
| 刚开机网卡未就绪 | 15 秒后重试 |
| 在校外（门户不可达） | 降频到 5 分钟一次，日志不刷屏 |

自启动用的是**计划任务**，不是「启动」文件夹。在 `taskschd.msc` 里能看到任务 `CampusNetAutoLogin`；「任务管理器 → 启动」页里不会有它。

## 常见问题

| 现象 | 处理 |
|---|---|
| 登录失败 | 点「打开日志」看门户原文；核对密码；运营商账号加后缀 |
| 提示密码解密失败 | DPAPI 绑定当前 Windows 用户，换账户/换机器后必须重填密码 |
| 改了脚本没生效 | 自启动跑的是 `%LOCALAPPDATA%` 里的副本，重新运行 `install.ps1` 同步 |
| 桌面图标变白块 | 重新运行 `install.ps1`，必要时重启资源管理器 |
| 学校门户不是 10.8.0.3 | 在界面里改「门户地址」，或在 `setup` 时用 `-Portal` 指定 |
| 想彻底清掉 | 运行 `卸载.cmd`，按提示选择是否删除配置目录 |

## 安全说明

**密码怎么存**：Windows DPAPI（当前用户范围）加密，`config.json` 里只有密文。密文与当前 Windows 账户绑定，拷到别的电脑或别的账户都解不开。

**密码会去哪**：只发往你填写的门户地址。密码不写进日志、不出现在计划任务命令行、不会上传到任何地方。项目没有任何统计或遥测代码。

**必须知道的限制**：

- 校园门户通常只提供 HTTP，密码在局域网内以明文传输，同网段抓包可见。这不是本工具的缺陷，是门户协议本身的限制；换任何客户端（包括官方客户端）都一样。
- DPAPI 防的是「别的用户、别的机器」，**不防「同一个 Windows 账户」**。谁能登进你的账户，谁就能解出密码。
- 自启动是当前用户级的计划任务，脚本位于 `%LOCALAPPDATA%`。该账户一旦被恶意软件控制，脚本可以被篡改——这是所有用户级自启动的通病。

完整的威胁模型与漏洞报告方式见 [SECURITY.md](SECURITY.md)。
